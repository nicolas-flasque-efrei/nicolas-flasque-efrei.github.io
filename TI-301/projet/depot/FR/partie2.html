TI301 – Algorithmique et Structures de données 2 · Projet « La forêt et la lumière »

Récupérer les fichiers de la partie 2

Les fichiers fournis pour la partie 2 ont été ajoutés au dépôt modèle du projet :

https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627

Vous allez les copier dans le dépôt de votre équipe, sans toucher à votre travail de la partie 1. Chaque commande se copie avec le bouton Copier de son cadre.

Le principe

  • La partie 2 n'ajoute que des fichiers nouveaux (16 fichiers) : aucun fichier de la partie 1 n'est modifié.
  • Votre dépôt a été créé à partir du dépôt modèle, mais il n'a pas d'historique commun avec lui : on ne fusionne pas les deux dépôts, on copie seulement les nouveaux fichiers, en les nommant un par un.
  • Un seul membre de l'équipe fait les parties A à C ; les autres font ensuite la partie D.

A · Avant de commencer un seul membre

  1. Ouvrez le projet de l'équipe dans CLion.
  2. Récupérez le travail des autres : Git → Update Project (Ctrl+T).
  3. Ouvrez le terminal de CLion : View → Tool Windows → Terminal (Alt+F12). Il s'ouvre dans le dossier du projet.
  4. Vérifiez que tout votre travail est commité : 
    git status
    • La réponse contient nothing to commit, working tree clean → passez à la partie B.
    • Sinon : Git → Commit (Ctrl+K), puis Git → Push (Ctrl+Shift+K), et recommencez l'étape A4.

B · Récupérer les fichiers de la partie 2 le même membre

Toutes les commandes se tapent dans le terminal de CLion, dans l'ordre.

  1. Déclarez le dépôt modèle sous le nom modele (une seule fois pour tout le projet) : 
    git remote add modele https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git
    • Message remote modele already exists : c'est déjà fait, passez à l'étape B2.
  2. Téléchargez le contenu du dépôt modèle, sans rien modifier dans votre projet : 
    git fetch modele
  3. Copiez les 16 nouveaux fichiers dans votre projet. Copiez le cadre entier : ses neuf lignes s'exécutent l'une après l'autre (si CLion demande de confirmer le collage de plusieurs lignes, acceptez). 
    git checkout modele/main -- cmake/partie2.cmake
git checkout modele/main -- data/foret_exemple.txt
git checkout modele/main -- include/arbre_foret.h include/croissance_lumiere.h
git checkout modele/main -- include/foret.h include/sauver_foret.h
git checkout modele/main -- src/arbre_foret.c src/croissance_lumiere.c
git checkout modele/main -- src/foret.c src/sauver_foret.c
git checkout modele/main -- src/main_p2_etape1.c src/main_p2_etape2.c
git checkout modele/main -- src/main_p2_etape3.c src/main_p2_etape4.c
git checkout modele/main -- src/main_p2_etape5.c src/main_p2_etape6.c
  4. Vérifiez : 
    git status
    • Vous devez voir 16 lignes new file:, et aucune ligne modified:.
    • Une ligne modified: : arrêtez-vous et voyez En cas de problème.
  5. Commitez et poussez les nouveaux fichiers : 
    git commit -m "Partie 2 : fichiers fournis"
git push

C · Vérifier dans CLion le même membre

  1. Rechargez le projet CMake : Tools → CMake → Reload CMake Project, ou clic droit sur CMakeLists.txt → Reload CMake Project.
  2. En haut à droite, la liste des configurations contient maintenant p2_etape_1 à p2_etape_6, en plus de celles de la partie 1.
  3. C'est normal si aucune de ces cibles ne compile pour l'instant : chaque programme src/main_p2_etapeN.c fourni fait les essais de validation de son étape, et ne compile qu'une fois toutes les fonctions de cette étape écrites (p2_etape_1 après l'étape 1, et ainsi de suite).
  4. Si une erreur de compilation désigne un fichier de la partie 1 (compilés avec ceux de la partie 2), corrigez-la d'abord.

D · Les autres membres de l'équipe chaque autre membre

  1. Une fois que le premier membre a poussé (étape B5) : Git → Update Project (Ctrl+T).
  2. Rechargez le projet CMake, comme à l'étape C1.
  3. Vous n'avez rien d'autre à faire : ni git remote add, ni git fetch, ni git checkout.

À ne pas faire

  • git pull modele main ou git merge modele/main : les deux dépôts n'ont pas d'historique commun, Git signalerait des conflits sur tous les fichiers de la partie 1.
  • Copier des dossiers entiers (git checkout modele/main -- src include) : vos fichiers de la partie 1 seraient remplacés par ceux du dépôt modèle, et votre travail effacé.
  • Faire les étapes B1 à B5 à plusieurs : un seul membre récupère les fichiers, les autres font Update Project.
  • Renommer ou déplacer les fichiers fournis : les cibles p2_etape_… de cmake/partie2.cmake ne les trouveraient plus.

En cas de problème

SymptômeQue faire
remote modele already existsRien : passez à l'étape B2.
pathspec … did not match any file(s) known to gitL'étape B2 n'a pas été faite, ou l'adresse du dépôt modèle est fausse. Vérifiez avec git remote -v : la ligne modele doit indiquer https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git. Sinon : git remote remove modele, puis recommencez à l'étape B1.
git status affiche une ligne modified: à l'étape B4Un de vos fichiers porte le nom d'un fichier fourni et vient d'être remplacé. Ne commitez pas : git checkout HEAD -- <fichier> lui rend votre version, puis prévenez votre enseignant.
Vous avez lancé un git merge ou un git pull, et Git signale des conflitsgit merge --abort annule tout ; reprenez à l'étape B3.
Les cibles p2_etape_… n'apparaissent pasRechargez le projet CMake (étape C1) ; vérifiez que cmake/partie2.cmake existe dans le projet.
Push rejected à l'étape B5Git → Update Project (Ctrl+T), puis git push.
