TI301 – Algorithmique et Structures de données 2 · Projet « La forêt et la lumière »

Créer le dépôt Git de votre équipe

Votre enseignant vous a fourni le lien du dépôt modèle (template) du projet :

https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627

Vous n'allez pas travailler dans ce dépôt modèle : vous allez en créer une copie privée, propre à votre équipe (trinôme, ou quadrinôme selon votre groupe). Suivez les étapes dans l'ordre.

Prérequis chaque membre, une seule fois

  1. Créez un compte GitHub si vous n'en avez pas : ouvrez github.com/signup et suivez les instructions.
  2. Notez votre nom d'utilisateur GitHub et donnez-le à vos coéquipiers.
  3. Vérifiez que Git est installé : ouvrez un terminal et tapez git --version.
    • Un numéro de version s'affiche → passez à l'étape P4.
    • Message d'erreur → installez Git for Windows depuis git-scm.com/download/win (options par défaut), puis recommencez l'étape P3.
  4. Configurez votre identité Git, dans le même terminal (remplacez par vos nom et prénom) : 
    git config --global user.name "Prénom Nom"
git config --global user.email "nom.prenom@efrei.net"
  5. Reliez CLion à votre compte GitHub :
    1. ouvrez CLion ;
    2. File → Settings → Version Control → GitHub ;
    3. cliquez sur +, puis Log In via GitHub… ;
    4. dans le navigateur qui s'ouvre, cliquez sur Authorize ;
    5. revenez dans CLion : votre compte apparaît dans la liste → OK.

A · Créer le dépôt de l'équipe un seul membre

Choisissez un membre de l'équipe. Les autres attendent la partie C.

  1. Suivez le lien fourni github.com/nicolas-flasque-efrei/TI301_PRJ_2627, en étant connecté à GitHub.
  2. Créez un nouveau dépôt : bouton vert Use this template (en haut à droite) → Create a new repository.
  3. Owner : sélectionnez votre compte.
  4. Repository name : tapez TI301_projet_<groupe>_<nom1>_<nom2>_<nom3>, suivi de _<nom4> si l'équipe compte 4 membres (exemple : TI301_projet_SC4_dupont_martin_durand). Utilisez le générateur ci-dessous :

    Générateur du nom du dépôt

    Nom du dépôt à copier dans Repository name :

  5. Visibility : cochez Private (obligatoire).
  6. Include all branches : laissez décoché.
  7. Cliquez sur Create repository.
  8. Vérifiez sur la page qui s'affiche :
    • l'adresse commence par https://github.com/<votre-compte>/ ;
    • la mention Private figure à côté du nom du dépôt.

B · Inviter l'équipe et l'enseignant le même membre

  1. Sur la page de votre dépôt, cliquez sur l'onglet Settings.
  2. Menu de gauche : Collaborators.
  3. Cliquez sur Add people.
  4. Tapez le nom d'utilisateur GitHub d'un coéquipier → sélectionnez-le → Add … to this repository.
  5. Recommencez l'étape B4 pour chaque coéquipier.
  6. Recommencez l'étape B4 pour votre enseignant : nicolas-flasque-efrei. Avant de valider, vérifiez à l'avatar affiché à côté du nom que c'est bien le compte de votre enseignant, et non un compte au nom proche.

C · Récupérer le dépôt dans CLion chaque membre

  1. Les invités seulement : acceptez l'invitation, depuis l'e-mail reçu ou depuis github.com/notifications → Accept invitation.
  2. Ouvrez la page du dépôt de l'équipe (pas celle du dépôt modèle).
  3. Cliquez sur le bouton vert Code → onglet HTTPS → icône de copie de l'adresse (elle se termine par .git).
  4. Dans CLion :
    • écran d'accueil : Get from VCS ;
    • ou, si un projet est ouvert : File → New → Project from Version Control…
  5. URL : collez l'adresse copiée à l'étape C3.
  6. Directory : choisissez un dossier hors de OneDrive (exemple : C:\TI301\projet).
  7. Cliquez sur Clone.
  8. Si CLion le demande : Trust Project.
  9. Attendez la fin du chargement du projet CMake (barre de progression en bas de la fenêtre).

D · Vérifier que tout fonctionne chaque membre

  1. En haut à droite de CLion, ouvrez la liste des configurations : vous devez voir etape_1, etape_2, etape_4 et foret.
  2. Sélectionnez etape_1.
  3. Cliquez sur ▶ (Run).
  4. Le programme s'exécute et lit les fichiers du dossier data/ : c'est prêt.
    • S'il ne trouve pas data/… : Run → Edit Configurations… → Working directory doit être le dossier du projet (voir l'étape 1 du sujet).

E · À chaque séance de travail chaque membre

  1. Avant de commencer : Git → Update Project (Ctrl+T) pour récupérer le travail des autres.
  2. Travaillez : évitez de modifier le même fichier en même temps qu'un coéquipier.
  3. Dès qu'une fonction compile et passe son test : Git → Commit (Ctrl+K), cochez les fichiers modifiés, écrivez un message précis (« growBud : tirage des directions »), puis Commit.
  4. Avant de partir : Git → Push (Ctrl+Shift+K) → Push.
    • Si le push est refusé (rejected) : refaites l'étape E1, puis l'étape E4.

À ne pas faire

  • Cloner directement le dépôt modèle : vous ne pourrez jamais y pousser votre travail.
  • Cliquer sur Fork : un fork d'un dépôt public est public, votre travail serait visible de tous.
  • Créer le dépôt en Public (si c'est fait : Settings → General → Danger Zone → Change visibility → Private).
  • Créer un dépôt par membre : l'équipe partage un seul dépôt.
  • Télécharger le ZIP du dépôt modèle : vous n'auriez pas de dépôt Git relié à GitHub.
