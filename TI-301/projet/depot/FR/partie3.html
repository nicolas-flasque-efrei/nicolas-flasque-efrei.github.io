Récupérer les fichiers de la partie 3

Les fichiers fournis pour la partie 3 ont été ajoutés au dépôt modèle du projet :

https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627

Vous allez les copier dans le dépôt de votre équipe, sans toucher à votre travail des parties 1 et 2. Chaque commande se copie avec le bouton Copier de son cadre.

Le principe

  • La partie 3 n'ajoute que des fichiers nouveaux (14 fichiers) : aucun fichier des parties 1 et 2 n'est modifié.
  • Votre dépôt a été créé à partir du dépôt modèle, mais il n'a pas d'historique commun avec lui : on ne fusionne pas les deux dépôts, on copie seulement les nouveaux fichiers, en les nommant un par un.
  • Un seul membre de l'équipe fait les parties A à C ; les autres font ensuite la partie D.
  • Si la procédure échoue et que En cas de problème ne suffit pas, une procédure de secours existe : un fichier .zip à décompresser dans votre projet.

A · Avant de commencer un seul membre

  1. Ouvrez le projet de l'équipe dans CLion.
  2. Récupérez le travail des autres : Git → Update Project (Ctrl+T).
  3. Ouvrez le terminal de CLion : View → Tool Windows → Terminal (Alt+F12). Il s'ouvre dans le dossier du projet.
  4. Vérifiez que tout votre travail est commité : 
    git status
    • La réponse contient nothing to commit, working tree clean → passez à la partie B.
    • Sinon : Git → Commit (Ctrl+K), puis Git → Push (Ctrl+Shift+K), et recommencez l'étape A4.

B · Récupérer les fichiers de la partie 3 le même membre

Toutes les commandes se tapent dans le terminal de CLion, dans l'ordre.

  1. Déclarez le dépôt modèle sous le nom modele (une seule fois pour tout le projet : si vous l'avez fait pour la partie 2, c'est déjà fait) : 
    git remote add modele https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git
    • Message remote modele already exists : c'est déjà fait, passez à l'étape B2.
  2. Téléchargez le contenu du dépôt modèle, sans rien modifier dans votre projet (à refaire pour la partie 3, même si vous l'avez fait pour la partie 2) : 
    git fetch modele
  3. Copiez les 14 nouveaux fichiers dans votre projet. Copiez le cadre entier : ses six lignes s'exécutent l'une après l'autre (si CLion demande de confirmer le collage de plusieurs lignes, acceptez). 
    git checkout modele/main -- cmake/partie3.cmake
git checkout modele/main -- data/test_analyse.csv data/test_asymetrie.csv data/test_histo.csv
git checkout modele/main -- include/campagne.h include/statistiques.h
git checkout modele/main -- src/campagne.c src/statistiques.c
git checkout modele/main -- src/main_p3_etape1.c src/main_p3_etape2.c src/main_p3_etape3.c
git checkout modele/main -- .run/p3_etape_1.run.xml .run/p3_etape_2.run.xml .run/p3_etape_3.run.xml
  4. Vérifiez : 
    git status
    • Vous devez voir 14 lignes new file:, et aucune ligne modified:.
    • Une ligne modified: : arrêtez-vous et voyez En cas de problème.
  5. Commitez et poussez les nouveaux fichiers : 
    git commit -m "Partie 3 : fichiers fournis"
git push

C · Vérifier dans CLion le même membre

  1. Rechargez le projet CMake : Tools → CMake → Reload CMake Project, ou clic droit sur CMakeLists.txt → Reload CMake Project.
  2. En haut à droite, la liste des configurations contient maintenant p3_etape_1 à p3_etape_3, en plus de celles des parties 1 et 2. Celles de p3_etape_1 et p3_etape_3 contiennent déjà des paramètres de ligne de commande (Run → Edit Configurations…, champ Program arguments).
  3. C'est normal si aucune de ces cibles ne compile pour l'instant : le programme fourni src/main_p3_etape2.c fait les essais de validation de l'étape 2, et ne compile qu'une fois les fonctions de cette étape écrites ; src/main_p3_etape1.c et src/main_p3_etape3.c sont fournis vides : c'est vous qui les écrivez.
  4. Si une erreur de compilation de p3_etape_1 désigne un fichier des parties 1 ou 2 (compilés avec ceux de la partie 3), corrigez-la d'abord.

D · Les autres membres de l'équipe chaque autre membre

  1. Une fois que le premier membre a poussé (étape B5) : Git → Update Project (Ctrl+T).
  2. Rechargez le projet CMake, comme à l'étape C1.
  3. Vous n'avez rien d'autre à faire : ni git remote add, ni git fetch, ni git checkout.

À ne pas faire

  • git pull modele main ou git merge modele/main : les deux dépôts n'ont pas d'historique commun, Git signalerait des conflits sur tous les fichiers des parties 1 et 2.
  • Copier des dossiers entiers (git checkout modele/main -- src include) : vos fichiers des parties 1 et 2 seraient remplacés par ceux du dépôt modèle, et votre travail effacé.
  • Faire les étapes B1 à B5 à plusieurs : un seul membre récupère les fichiers, les autres font Update Project.
  • Renommer ou déplacer les fichiers fournis : les cibles p3_etape_… de cmake/partie3.cmake ne les trouveraient plus.

En cas de problème

SymptômeQue faire
remote modele already existsRien : passez à l'étape B2.
pathspec … did not match any file(s) known to gitL'étape B2 n'a pas été faite, ou l'adresse du dépôt modèle est fausse. Vérifiez avec git remote -v : la ligne modele doit indiquer https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git. Sinon : git remote remove modele, puis recommencez à l'étape B1.
git status affiche une ligne modified: à l'étape B4Un de vos fichiers porte le nom d'un fichier fourni et vient d'être remplacé. Ne commitez pas : git checkout HEAD -- <fichier> lui rend votre version, puis prévenez votre enseignant.
Vous avez lancé un git merge ou un git pull, et Git signale des conflitsgit merge --abort annule tout ; reprenez à l'étape B3.
Les cibles p3_etape_… n'apparaissent pasRechargez le projet CMake (étape C1) ; vérifiez que cmake/partie3.cmake existe dans le projet, et que CMakeLists.txt se termine par la ligne include(cmake/partie3.cmake OPTIONAL) ; sinon, ajoutez-la et rechargez le projet CMake.
Un programme p3_etape_… ne trouve pas un fichier de data/ ou de output/Run → Edit Configurations… → Working directory doit être le dossier du projet : $ProjectFileDir$.
Push rejected à l'étape B5Git → Update Project (Ctrl+T), puis git push.

Procédure de secours un seul membre

Seulement si la partie B a échoué et que En cas de problème ne vous a pas permis de vous en sortir. Le .zip contient exactement les 14 mêmes fichiers.

  1. Récupérez le .zip : TI301_partie3_fichiers.zip.
  2. Décompressez-le : clic droit sur le fichier téléchargé → Extraire tout… Vous obtenez cinq dossiers : .run, cmake, data, include et src.
  3. Ajoutez les fichiers et les dossiers à votre projet : copiez ces cinq dossiers dans le dossier du projet (celui qui contient CMakeLists.txt). Windows fusionne chaque dossier avec celui du même nom.
    • Si Windows propose de remplacer un fichier, choisissez Ignorer ces fichiers : aucun fichier de vos parties 1 et 2 ne doit être remplacé.
  4. Commitez et poussez : Git → Commit (Ctrl+K), cochez les 14 nouveaux fichiers (rubrique Unversioned Files), message « Partie 3 : fichiers fournis », Commit and Push…
  5. Reprenez à la partie C (vérifier dans CLion) ; les autres membres font la partie D.

Retour au sujet de la partie 3.
