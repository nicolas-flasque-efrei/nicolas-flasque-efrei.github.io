TI301 – Algorithms and Data Structures 2 · Project “The Forest and the Light”

Create your team's Git repository

Your teacher has given you the link to the project's template repository:

https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627

You will not work in this template repository: you will create a private copy of it, owned by your team (three students, or four depending on your group). Follow the steps in order.

Prerequisites every member, once

  1. Create a GitHub account if you don't have one: open github.com/signup and follow the instructions.
  2. Write down your GitHub username and give it to your teammates.
  3. Check that Git is installed: open a terminal and type git --version.
    • A version number is displayed → go to step P4.
    • Error message → install Git for Windows from git-scm.com/download/win (default options), then repeat step P3.
  4. Set your Git identity, in the same terminal (use your own name): 
    git config --global user.name "Firstname Lastname"
git config --global user.email "lastname.firstname@efrei.net"
  5. Connect CLion to your GitHub account:
    1. open CLion;
    2. File → Settings → Version Control → GitHub;
    3. click +, then Log In via GitHub…;
    4. in the browser window that opens, click Authorize;
    5. back in CLion, your account appears in the list → OK.

A · Create the team repository one member only

Choose one member of the team. The others wait for part C.

  1. Follow the link you were given github.com/nicolas-flasque-efrei/TI301_PRJ_2627, while signed in to GitHub.
  2. Create a new repository: green Use this template button (top right) → Create a new repository.
  3. Owner: select your account.
  4. Repository name: type TI301_projet_<group>_<name1>_<name2>_<name3>, followed by _<name4> if your team has 4 members (example: TI301_projet_INT1_dupont_martin_durand). Use the generator below:

    Repository name generator

    Repository name to paste into Repository name:

  5. Visibility: select Private (mandatory).
  6. Include all branches: leave unchecked.
  7. Click Create repository.
  8. Check on the page that opens:
    • the address starts with https://github.com/<your-account>/;
    • the label Private appears next to the repository name.

B · Invite your team and your teacher the same member

  1. On your repository page, click the Settings tab.
  2. Left menu: Collaborators.
  3. Click Add people.
  4. Type a teammate's GitHub username → select it → Add … to this repository.
  5. Repeat step B4 for each teammate.
  6. Repeat step B4 for your teacher: nicolas-flasque-efrei. Before confirming, check the avatar shown next to the name to make sure it is your teacher's account, and not an account with a similar name.

C · Get the repository into CLion every member

  1. Invited members only: accept the invitation, from the e-mail you received or from github.com/notifications → Accept invitation.
  2. Open the team's repository page (not the template repository page).
  3. Click the green Code button → HTTPS tab → copy icon next to the address (it ends with .git).
  4. In CLion:
    • from the welcome screen: Get from VCS;
    • or, if a project is open: File → New → Project from Version Control…
  5. URL: paste the address copied in step C3.
  6. Directory: choose a folder outside OneDrive (example: C:\TI301\projet).
  7. Click Clone.
  8. If CLion asks: Trust Project.
  9. Wait until the CMake project has finished loading (progress bar at the bottom of the window).

D · Check that everything works every member

  1. At the top right of CLion, open the list of run configurations: you should see etape_1, etape_2, etape_4 and foret.
  2. Select etape_1.
  3. Click ▶ (Run).
  4. The program runs and reads the files in the data/ folder: you are ready.
    • If it cannot find data/…: Run → Edit Configurations… → Working directory must be the project folder (see step 1 of the project).

E · At every work session every member

  1. Before you start: Git → Update Project (Ctrl+T) to get your teammates' work.
  2. Work: avoid editing the same file as a teammate at the same time.
  3. As soon as a function compiles and passes its test: Git → Commit (Ctrl+K), tick the modified files, write a precise message (“growBud: drawing the directions”), then Commit.
  4. Before you leave: Git → Push (Ctrl+Shift+K) → Push.
    • If the push is rejected: repeat step E1, then step E4.

Do not

  • Clone the template repository directly: you will never be able to push your work to it.
  • Click Fork: a fork of a public repository is public, so your work would be visible to everyone.
  • Create the repository as Public (if you did: Settings → General → Danger Zone → Change visibility → Private).
  • Create one repository per member: the team shares a single repository.
  • Download the ZIP of the template repository: you would not have a Git repository linked to GitHub.
