TI301 – Algorithms and Data Structures 2 · Project “The Forest and the Light”

Getting the files of part 2

The files provided for part 2 have been added to the project's template repository:

https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627

You are going to copy them into your team's repository, without touching your part 1 work. Each command is copied with the Copy button of its box.

The principle

  • Part 2 only adds new files (16 files): no file of part 1 is modified.
  • Your repository was created from the template repository, but it has no common history with it: you do not merge the two repositories, you only copy the new files, naming them one by one.
  • Only one member of the team does parts A to C; the others then do part D.
  • If the procedure fails and Troubleshooting is not enough, a fallback procedure exists: a .zip file to unzip into your project.

A · Before you start one member only

  1. Open the team project in CLion.
  2. Get your teammates' work: Git → Update Project (Ctrl+T).
  3. Open the terminal of CLion: View → Tool Windows → Terminal (Alt+F12). It opens in the project folder.
  4. Check that all your work is committed: 
    git status
    • The answer contains nothing to commit, working tree clean → go to part B.
    • Otherwise: Git → Commit (Ctrl+K), then Git → Push (Ctrl+Shift+K), and do step A4 again.

B · Get the files of part 2 the same member

All the commands are typed in the CLion terminal, in this order.

  1. Declare the template repository under the name modele (once for the whole project): 
    git remote add modele https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git
    • Message remote modele already exists: it is already done, go to step B2.
  2. Download the content of the template repository, without changing anything in your project: 
    git fetch modele
  3. Copy the 16 new files into your project. Copy the whole box: its nine lines run one after the other (if CLion asks you to confirm pasting several lines, accept). 
    git checkout modele/main -- cmake/partie2.cmake
git checkout modele/main -- data/foret_exemple.txt
git checkout modele/main -- include/arbre_foret.h include/croissance_lumiere.h
git checkout modele/main -- include/foret.h include/sauver_foret.h
git checkout modele/main -- src/arbre_foret.c src/croissance_lumiere.c
git checkout modele/main -- src/foret.c src/sauver_foret.c
git checkout modele/main -- src/main_p2_etape1.c src/main_p2_etape2.c
git checkout modele/main -- src/main_p2_etape3.c src/main_p2_etape4.c
git checkout modele/main -- src/main_p2_etape5.c src/main_p2_etape6.c
  4. Check: 
    git status
    • You must see 16 new file: lines, and no modified: line.
    • A modified: line: stop and see Troubleshooting.
  5. Commit and push the new files: 
    git commit -m "Partie 2 : fichiers fournis"
git push

C · Check in CLion the same member

  1. Reload the CMake project: Tools → CMake → Reload CMake Project, or right-click on CMakeLists.txt → Reload CMake Project.
  2. At the top right, the list of configurations now contains p2_etape_1 to p2_etape_6, in addition to those of part 1.
  3. It is normal if none of these targets compiles for now: each provided program src/main_p2_etapeN.c runs the validation tests of its step, and only compiles once all the functions of that step are written (p2_etape_1 after step 1, and so on).
  4. If a compilation error points to a part 1 file (compiled together with those of part 2), fix it first.

D · The other members of the team every other member

  1. Once the first member has pushed (step B5): Git → Update Project (Ctrl+T).
  2. Reload the CMake project, as in step C1.
  3. You have nothing else to do: no git remote add, no git fetch, no git checkout.

Do not

  • git pull modele main or git merge modele/main: the two repositories have no common history, Git would report conflicts on every file of part 1.
  • Copy whole folders (git checkout modele/main -- src include): your part 1 files would be replaced by those of the template repository, and your work erased.
  • Do steps B1 to B5 with several members: one member gets the files, the others do Update Project.
  • Rename or move the provided files: the p2_etape_… targets of cmake/partie2.cmake would no longer find them.

Troubleshooting

SymptomWhat to do
remote modele already existsNothing: go to step B2.
pathspec … did not match any file(s) known to gitStep B2 was not done, or the address of the template repository is wrong. Check with git remote -v: the modele line must show https://github.com/nicolas-flasque-efrei/TI301_PRJ_2627.git. Otherwise: git remote remove modele, then start again at step B1.
git status shows a modified: line at step B4One of your files has the name of a provided file and has just been replaced. Do not commit: git checkout HEAD -- <file> gives it back your version, then tell your teacher.
You ran a git merge or a git pull, and Git reports conflictsgit merge --abort cancels everything; start again at step B3.
The p2_etape_… targets do not appearReload the CMake project (step C1); check that cmake/partie2.cmake exists in the project.
Push rejected at step B5Git → Update Project (Ctrl+T), then git push.

Fallback procedure one member only

Only if part B failed and Troubleshooting did not get you out of it. The .zip contains exactly the same 16 files.

  1. Get the .zip: TI301_partie2_fichiers.zip.
  2. Unzip it: right-click on the downloaded file → Extract All… You get four folders: cmake, data, include and src.
  3. Add the files and folders to your project: copy these four folders into the project folder (the one that contains CMakeLists.txt). Windows merges each folder with the one of the same name.
    • If Windows offers to replace a file, choose Skip these files: no file of your part 1 must be replaced.
  4. Commit and push: Git → Commit (Ctrl+K), tick the 16 new files (Unversioned Files section), message “Partie 2 : fichiers fournis”, Commit and Push…
  5. Go on with part C (check in CLion); the other members do part D.
